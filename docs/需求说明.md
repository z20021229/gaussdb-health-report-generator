# GaussDB 数据库季度巡检报告自动生成工具需求说明

## 背景

GaussDB 数据库季度巡检通常会产生压缩包、日志、文本、HTML 或其他导出文件。人工整理这些材料并编写 Word 报告耗时较长，且容易出现遗漏、格式不统一或结论不可追溯的问题。

本项目目标是建设一个自动化工具，将巡检包转换为结构化数据，并基于既有客户交付版 Word 报告样式生成正式的 GaussDB 数据库健康诊断报告。

## 输入

工具应支持 GaussDB 巡检包及相关巡检文件，例如：

- `.rar`
- `.tar.gz`
- `.zip`
- `.txt`
- `.html`
- `.log`

输入内容可能包含客户信息、数据库信息、节点信息、系统资源、数据库状态、容量使用、性能指标、配置检查、告警信息、慢 SQL 或其他巡检明细。

所有客户名称、节点 IP、数据库名、巡检日期、指标值和检查结论必须从输入文件解析获得，不能从样例报告或样例巡检包中硬编码。

## 处理

工具的处理能力包括：

1. 自动识别输入文件类型。
2. 自动解压巡检包。
3. 自动扫描解压后的文件清单。
4. 自动解析文本、HTML、日志和后续扩展格式。
5. 将解析结果转换为结构化 YAML。
6. 根据结构化数据执行风险分析。
7. 生成可追溯的中间文件、解析日志和附录路径。

如果某项内容无法解析，应统一输出“未采集”或“未提供”，不得编造数据、结论或建议。

## 输出

工具最终输出按照 Word 样例格式生成的：

```text
GaussDB 数据库健康诊断报告
```

同时输出结构化和中间结果：

- 巡检解析 YAML
- 风险分析 YAML
- 解析日志
- 中间文件
- 长明细附录路径

报告正文应面向客户交付，整体措辞正式、简洁、专业。对于慢 SQL、对象清单、日志明细、大容量列表等长内容，正文只展示 Top N 或摘要，完整内容保留到中间文件或附录路径。

## 核心流程

```text
巡检包 -> 解压 -> 解析 -> 风险分析 -> YAML -> Word 报告
```

各阶段说明：

1. 巡检包：用户提供 GaussDB 巡检结果包或单个巡检文件。
2. 解压：工具自动识别压缩格式并解压到工作目录。
3. 解析：工具扫描文件并提取客户、数据库、节点、指标和检查项。
4. 风险分析：根据解析结果生成风险等级、问题说明和整改建议。
5. YAML：将解析数据和风险分析结果写入结构化 YAML。
6. Word 报告：按照既有报告格式生成客户交付版 Word 文档。

## 非功能要求

- 解析器必须通用，不能依赖单一客户文件名、单一 IP、单一数据库名或单一节点数量。
- 工具应能在部分字段缺失时继续运行。
- 所有生成内容应可追溯到输入文件或结构化中间结果。
- 优先保证基础流程可运行，再逐步提升解析覆盖率。
- 后续每次修改应同步更新 README 和测试。
